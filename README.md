**PRD – Refinado no Copilot**

1. Contexto
O aplicativo será baseado em conversas em linguagem natural, permitindo que o usuário registre e acompanhe suas finanças sem precisar lidar com formulários complexos ou planilhas.

2. Problema
Usuários iniciantes em finanças pessoais costumam desistir de aplicativos tradicionais porque exigem muita entrada manual e oferecem pouca personalização. O desafio é criar uma experiência fluida e envolvente que simplifique o processo.

3. Público-Alvo
- Pessoas que querem começar a organizar suas finanças de forma prática.
- Usuários que buscam simplicidade e clareza, sem termos técnicos complicados.
- Principalmente iniciantes no controle financeiro.

4. Funcionalidades-Chave
1. Registrar gastos via chat em linguagem natural
   - Exemplo: “Gastei R$ 30 com almoço hoje.”
   - O sistema interpreta valor, categoria e data automaticamente.

2. Classificação automática das transações
   - Categorias como alimentação, transporte, lazer, contas fixas.
   - Possibilidade de correção manual pelo usuário.

3. Definir e acompanhar metas financeiras
   - Exemplo: “Quero economizar R$ 500 em 3 meses.”
   - Barra de progresso simples e visual.

4. Visualizar relatórios simples e personalizados
   - Gráficos básicos (pizza para categorias, linha para evolução mensal).
   - Resumo em linguagem clara: “Você gastou 15% a mais em transporte este mês.”

5. Valor disponível para gasto diário no mês
   - Cálculo automático com base nas entradas (receitas) e nos gastos já registrados.
   - Exibição em formato simples: “Você pode gastar até R$ 50 por dia para manter seu orçamento.”
   - Atualização dinâmica conforme novos gastos são adicionados.

5. Entregável da IA
Um plano de MVP com:
- Principais telas (chat, metas, relatórios, cálculo diário).
- Recursos necessários (NLP, banco de dados, motor de classificação).
- Esboço de validação inicial com grupo piloto.

6. Recursos Necessários
- NLP (Processamento de Linguagem Natural) para interpretar mensagens.
- Motor de classificação automática para categorizar gastos.
- Banco de dados simples para armazenar transações e metas.
- Interface conversacional amigável e intuitiva.
- Módulo de cálculo orçamentário para estimar valor disponível por dia.

7. Design Universal
- O aplicativo deve ser projetado para oferecer boa experiência ao maior número possível de usuários, independentemente de idade, nível de familiaridade com tecnologia ou eventuais limitações.
- Princípios aplicados:
  - Clareza visual: textos legíveis, contraste adequado, ícones intuitivos.
  - Acessibilidade: suporte a leitores de tela, navegação simplificada.
  - Inclusão: linguagem simples e educativa, evitando termos técnicos.
  - Flexibilidade: adaptação a diferentes tamanhos de tela e dispositivos.

- # Resumo das Funcionalidades – Talk Money Buddy

## Funcionalidades Implementadas
- **Valor disponível para gasto diário**
  - Mostra quanto o usuário pode gastar por dia para manter o orçamento mensal.
  - Atualização dinâmica conforme novos gastos são registrados.

- **Resumo financeiro do mês**
  - Exibição de receitas totais.
  - Gastos acumulados.
  - Saldo atualizado do mês.

- **Gastos por categoria**
  - Distribuição automática em categorias como alimentação, transporte, lazer, contas fixas, saúde e educação.
  - Visualização clara dos valores em cada categoria.

- **Histórico de gastos recentes**
  - Lista de transações com descrição, data e valor.
  - Exemplos: almoço no restaurante, Uber, cinema, conta de luz, supermercado.

- **Navegação principal**
  - Acesso rápido às seções: Chat, Metas e Relatórios.
  - Registro de gastos diretamente pelo chat.

---

## Alinhamento com o PRD
- **Chat para registrar gastos em linguagem natural** → já previsto, com botão para registrar gasto.  
- **Classificação automática das transações** → presente, com categorias atribuídas.  
- **Definição e acompanhamento de metas** → aparece como seção, mas ainda pouco detalhado.  
- **Relatórios simples e personalizados** → disponíveis com gráficos e resumo por categoria.  
- **Valor disponível para gasto diário** → implementado e visível na tela inicial.  
- **Design universal** → interface simples, clara e acessível, com ícones e textos diretos.

- Uma breve **reflexão sobre o processo**:
  - Foi fantástico aprender sobre vibe coding e formulçao do PRD
  - Excluir o assistente bagunçou um pouco o processo e a transferência para o Lovable foi um horror!!
  - A limitação de interações gratuitas no lovable foi frustrante, mas tentarei fazê-lo novamente quando tiver maior prática com os prompts.
  - O principal foi perceber que para conversar com IAs é necessário ter clareza do problema, contexto, público e resposta esperada (não necessáriamente o resultado desejado, no meu caso)...
  - Achei fantástico! O maior desafio foi comprender a formulação correta do PRD desenvolver as soluções e o mais interessante foi observar as diferenças nos resultados pelas alterações no PRD e respostas às questões das IAs.
